# 提炼与合并

## 从材料选择输出

| 材料 | 重点提取 | 应核对 |
|---|---|---|
| 教程 / 指南 | 前置条件 → 输入 → 动作 → 分支 → 输出 | 命令版本、成功信号、关键图示 |
| 故障复盘 | 现象 → 排查 → 证据 → 修复 → 预防 | 已证实原因与假设分开 |
| 选型 / 对比 | 条件、约束、取舍、反例 | 基准环境、作者立场、数据日期 |
| 工具介绍 | 对应官方项目、接口、可组合动作 | 真实 CLI/API、许可、运行依赖 |
| 优秀范例 | 输出结构、可观察的质量特征 | 推导的方法标记为推断，用新输入验证 |
| 方法论 / 访谈 | 有条件的决策、检查标准 | 发言人归属，引用语与作者观点分开 |
| 文档 / 参数 | 非显然默认值、组合约束、失败模式 | 适用版本、废弃项、官方出处 |
| 新闻 / 榜单 / 感想 | 是否存在值得重复的操作规则 | 没有就 skip；工具榜单不逐项凑 skill |

## 生成前写一份简短提炼判断

明确“以后在什么请求下，拿什么输入，能得到什么输出”。标明工作流、工具调用或参考查询；写出材料的贡献与缺口。用户只要求分析时到这里结束。

按能力而非篇数划分，避免所有材料合成一个笼统技能，也避免每段拆成碎技能。一个能力跨多个来源时，来源清单保留每篇的具体贡献。

## 合并既有技能

先读旧 SKILL.md 和本次涉及的引用、脚本及验收记录。分类记录：

- 新增：补到对应步骤或 reference。
- 重复：保留一个规则，新增来源支持。
- 修订：核对官方资料和目标环境；保留仍适用的旧分支。
- 冲突：比较来源权威性、版本、环境和验证证据；不能用文章更晚或重复次数更多直接裁决。

保留用户已确认的本机规则。第三方原版不改，生成另名适配版；明确要求更新本机原创时可由 agent 备份后编辑，CLI 不自动接管未管理目录。更新的验收应覆盖实际改变的行为，不能用旧验收文件证明新行为。

## 语义验收

对 workflow：给新的实际输入，按步骤产出结果，再核对是否满足交付标准。

对 tool：在临时样例目录运行经过阅读且获准执行的代码，检查真实文件、返回值或接口结果。缺依赖时先交候选稿；无执行证据就标未验证。

对 reference：用具体问题定位正确条目，核对适用条件和来源；再用材料未覆盖的问题验证能否准确指出缺失。

不要把示例输出直接充当运行输出。验收 JSON 是 agent 的记录，辅助校验器不能判断内容是否真实；由执行者对观察负责。
