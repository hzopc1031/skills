# 文档整理交付模板

模板用于提醒需要报告的内容，不要求原样复制全部栏目。只填写实际做过或来源可证实的信息，未知项明确标注；不要把模板占位符放进最终业务正文。报告和原文可能含业务信息，不默认上传 GitHub 或其他平台。

## 一、整理正文

默认另存 `<原名>-kb.md`；原文件不覆盖。图片和附件保留可解析路径，资源复制范围依据用户授权。正文不包含工具执行日志、修改流水或未经验证的补充事实。

如果要求覆盖，先记录备份位置；如果只有格式整理授权，不把章节重组或内容合并藏在输出中。

## 二、修改摘要

建议另存 `<原名>-changes.md`，也可放在交付回复中。

```text
类型与范围：通用 / 问题分析 / 混合；列明涉及章节。
授权边界：仅格式 / 已获结构重组授权；不明确的部分未执行。
目标配置：平台和版本（如已知）、分段方式、长度上限及单位。
未确认的假设：明确列出，不把检查器默认值说成平台真实配置。
输出与资源：整理正文的位置、附件处理、原文或备份位置。
```

**章节对应与改动**：每项记录原位置 → 输出位置、操作和原因。没有重排就写“章节顺序未变”；没有核对所有内容就不要声称“全文无遗漏”。

**内容保护复核**：分别写清代码/命令、数字与单位、版本与日期、路径与链接、表格关系等核对了哪些、用何种方式核对、发现什么。检查器当前不提供这些保真对比。

**检查结果**：记录实际命令或等价参数、近似模型、error/warning/info 数量，以及逐条警告的取舍。不能只写“通过”忽略仍有警告；`--strict` 的门禁失败不等同于警告已成为事实错误。

**平台验证**：已执行还是未执行；只记录实际分段预览、实际提问和返回证据，不编造命中率。

## 三、待确认事项

建议另存 `<原名>-review.md`，也可与修改摘要合并。

每项写：原文位置、问题、影响、需要用户提供/决定什么，以及相关改动是否暂停。常见情形：

- 不知道目标知识库的分隔符或长度单位；暂不为默认参数批量删空行。
- 同一指标的数值不一致但采样时点不明；原值保留，尚未选取“正确值”。
- 根因或恢复能力缺证据；保留“未确认”，没有补写结论。
- 代码、表格或图片无法安全拆分/转换；保留原内容，等待目标配置或资源。
- 只获格式授权，但需要重排章节；先提供建议，不执行重组。

没有发现未决项时写“本地复核未发现未决项；平台效果的验证状态见修改摘要”，不能借此声称所有事实和检索效果已验证。

## 四、检索验证小清单

在用户授权的目标平台、同一套配置下，选择 3–5 个由原文能够回答的问题。若未授权访问平台，交付这份测试计划，不自行上传业务数据。

每个问题记录：问题、原文依据、期望找到的对象与前提、实际返回片段/位置、是否足以回答、是否混入其他主题。

对比整理前后时尽量只变动文档版本，保持检索配置一致。没有实测数据只写预期和待验证，不说“召回提升”或编造百分比。
