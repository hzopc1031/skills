## 原版与运行版脚本

[照片原版脚本快照](<check_doc.photo-original.py.txt>)为按照片恢复的 153 行源码，原始 SHA-256：

```text

```

该快照用于核对，不是推荐运行入口；后缀 `.txt` 是有意保留的。原注释中的正则反斜线数量有微小识读不确定，恢复为单个 `\s`，可能触发 Python 的无效转义警告。

[运行版检查器](<../scripts/check_doc.py>)保留原版的标题/空行模型、60 字符碎块阈值和默认 2048 字符上限，做了以下明确区分的小修：

- 使用 raw docstring，消除原注释反斜线警告；不再把“与 Dify 1.x 一致”写成已验证保证。
- 空文档、空标题、没有正文的章节不会再使 `max()` 崩溃或静默通过，会给出待处理提示。
- 首标题前的正文和无标题正文不再静默丢失，保留为无标题内容并提示补充标题。
- 只剥离标题前缀，保留 `C#`、`#标签` 等标题文字中的井号。
- 章节内部仅有一个空行时也报告行号，排除真正的章节末尾分隔空行。
- 参数必须是正整数；多余参数、无法读取文件和 UTF-8 解码错误返回 `2`，不输出未处理的异常回溯。
- 接受 UTF-8 BOM；文件通过上下文管理器读取并关闭。
- 三级标题统计不再把三反引号围栏中的示例标题算作正文标题。

这些修正没有改写照片中的规范正文。主规范新增了版本适用说明、正确运行路径和退出码解释，避免把近似检查误当成真实入库结果。

## 保留的模型限制

- 不是完整 Markdown 解析器：仅在行首识别 `^#+\s`，使用三反引号简单切换围栏状态；不处理所有波浪线围栏、嵌套围栏和 Markdown 扩展。
- 按字面 `\n\n` 拆块；仅含空格的空行、代码围栏内的空行与真实平台行为可能不同。
- 不会执行真实超长硬切，不计算 token、嵌入向量、分段重叠或召回质量。
- 表格只按块是否以 `|` 开头识别；孤儿引导句按前一块是否小于 100 字符启发判断，可能误报。
- 规范允许人工判断保留表格，但运行版仍会对单标题多块返回 `1`，不能将返回 `1` 等同于一律禁止上传。
- `###` 只统计不单独阻断；不同文档类型要人工判断，不能把统计数量当作统一违规数。

照片内关于表格渲染和 Dify 抽取器的说法，保留为源规范的假设。不同版本、解析器与知识库配置需要实际预览确认；本次没有连接或上传到 Dify。
