## 二、第一轮可运行复原的历史修正

首次发布的运行版曾修正空文档崩溃、首标题前正文丢失、标题内 `#` 丢失、单个内部空行漏计和无效参数异常等问题；当时通过 28 项单元测试及 4 项命令行检查。这个计数仅指第一轮基线，不代表当前优化版。

当时仍以“标题 + 空行”为单一模型，把短块和多块统一列为需处理。本轮有意改变这些行为，不再把它们当作不可调整的照片规则。

## 三、用户授权的优化版

当前执行规范见 [Skill 主入口](<../SKILL.md>)，本次修改不是对照片的逐字转录。

### 工作方法

- 先确认文档类型、目标分段配置及改动授权；配置不明时保守整理，不以检查器默认值代替平台实际配置。
- 一个入口分通用、问题分析、混合三条路径；混合文档按章节分流。
- 从“块数必须等于标题数”改为语义完整优先，允许合理短块、多块、表格与独立的三级标题。
- 保护代码、命令、日志、数字与单位、版本、路径、引用和限定条件；默认另存原文之外的整理稿。
- 结构性修改需要本次授权；缺失证据进入待确认，不能补造根因或恢复结果。
- 问题分析六栏改为参考，保留并行因果与来源支持的配置判据，删除强找矛盾及存储案例一刀切要求。
- 新增 [交付模板](<report-template.md>)：整理正文、修改摘要、待确认事项，以及真实检索验证计划。

### 只读检查器

[运行入口](<../scripts/check_doc.py>)新增两种近似分块模型、可配置字符阈值、error/warning/info 分级、严格门禁和 JSON 输出。旧式 `文档.md 2048` 调用仍支持。

- 默认：仅 error 导致退出 `1`；有 warning 而无 error 返回 `0`，不能称为“无风险通过”。
- `--strict`：warning 也导致退出 `1`，只是门禁选择，不是把启发式提示升级成已证实问题。
- 参数、文件或 UTF-8 编码错误返回 `2`；JSON 模式也提供可解析错误报告。
- 扫描保护常见反引号/波浪线围栏及缩进代码；代码内部空行与标题不作为普通分隔点。保护行为仅属于本地近似模型，不代表目标平台一定这样处理。
- 报告只包含模型、参数、行号和块的结构信息，不输出正文片段；标题、文件名仍可能敏感，报告不得默认公开。

## 四、剩余限制与实际验证

- 不是完整 Markdown 或 HTML 解析器，不覆盖所有列表/表格扩展、Setext 标题、复杂嵌套容器或自定义平台语法。
- 不模拟真实 token 分段、重叠、父子分段、嵌入、排序或超长硬切；上限与短块阈值均为字符，统计仅供提示。
- 表格引导句等是启发式检查，可能误报；不会判断主题是否混杂、因果是否成立，或原文是否遗漏。
- 代码或表格不可安全拆分时应保留并报告，不自动截断、不执行命令、不擅自调高平台上限。
- 文档修改由 AI/人工按规则完成，脚本不改写源文件，不做原文保真对比，不转换 Office，不上传业务文档。
- 尚未连接特定 Dify 实例验证。分段预览和真实提问需要另外授权，不能从本地测试推导召回效果已提升。

本轮在仓库根目录实际运行 `python -B -m unittest discover -s tests -v`，64 项全部通过（60 项检查器回归 + 4 项仓库契约），无跳过或预期失败。覆盖分级、两种模型、配置边界、JSON 错误报告、代码区域、标题处理，以及三个历史快照哈希。

另外实际运行 [Windows CLI 集成脚本](<../../tests/smoke_cli.ps1>)，15 项全部通过：正常、默认警告、严格门禁、仅标题模型、超长、无效阈值、缺失文件、旧参数、围栏保护、空文档、未闭合围栏、无效 UTF-8、BOM/CRLF 及参数冲突等。输入文件检查前后 SHA-256 一致；临时合成数据已按核对后的路径清理。真实业务文档的语义和检索效果不在这些测试结论内。
