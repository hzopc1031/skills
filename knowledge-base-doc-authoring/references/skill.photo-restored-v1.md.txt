# 知识库文档编写规范

> 适用说明：正文按用户提供的照片恢复，采用照片中的“标题 + 空行”切块模型；不同 Dify 版本、抽取器与分段配置可能不同，须用目标知识库的真实预览复核。自检脚本是近似检查，不是官方分块器。复原来源、脚本小修与限制见 [复原说明](<references/restoration-notes.md>)。不要把本技能说明文件自身当作待入库正文执行此排版规则。

文档进知识库会被切块、单独召回。**块的边界只有两个：空行、`#` 标题行**——Dify 的 markdown 抽取器先按 `^#+\s` 拆成多个 Document（标题行成为首行、`#` 被剥离），再对每个 Document 按空行切块，块与块不合并，只有单块超过「分段最大长度」才硬切。

所以处理任何文档，目标都是同一句话：**本该在一块的内容之间，不留空行、不加小标题。**

## 一、两条处理路径

| 文档类型 | 做什么 | 读哪里 |
| --- | --- | --- |
| **问题分析类**：有现象、根因、判断依据、修复动作 | 结构改写（六章）+ 排版 | [references/fault-analysis.md](<references/fault-analysis.md>) |
| **通用类**：操作手册、方案说明、规范、其它 | **只处理换行与标题，不动内容与结构** | 本文第三节 |

判据：读者是要「判断这是不是同一个问题、怎么修」（问题分析），还是「照着做 / 理解设计」（通用）。问题分析类的组织方式反直觉，必须按 reference 改写；通用类的内容组织由原文决定，不要重排章节、不要合并主题。

## 二、排版核心（两条路径共用）

1. **一个标题 = 一个块。** 标题与正文之间、正文各段之间都不留空行；全文块数应等于标题数。
2. **不用 `###` 切小节**：每个 `###` 开启新 Document。下级内容写成加粗引导句，与正文同段。真正独立的主题才用标题。
3. **段内分条用单换行**，不要用空行；单换行不切块。
4. **需要换行渲染就用 `-` 或 `1.`**：列表可以打断段落，不产生空行也能分行显示。
5. **表格会强制多切一块**：表格前必须有空行才渲染，于是「引导句」与「表格」必然两块。映射类内容改列表 `- **标签：** 内容`；确实要留表格时，让引导句自带结论，别写「下表按……排列」。
6. **单块控制在分段上限内**（常见 2048 / 4000），超过会被无标题硬切；附录、长章节先估算再定上限。
7. **不用 `---` 水平线**，不用 HTML 标签（抽取器会剥掉）。
8. **术语与数字统一**：本例 / 本案例 / 本环境选一个；前后数字必须对得上，差额要有解释。

## 三、通用类：只处理换行与标题

不做章节重排、不改写内容、不合并主题。只做三件事：**判断哪些内容本该在一块 → 压掉它们之间的空行 → 把不必要的小标题降级成加粗引导句。**

**怎么判断「本该在一块」：**

- 同一个操作模块的步骤、注意事项、配图；
- 同一个论点的提出、展开、举例；
- 图/表与它的说明文字；
- 同一对象的并列属性（如各组件在各节点上的分布）。

反过来，**主题切换处保留一个空行或一个标题**——不要为了少块把两个不同主题硬压在一起，那会让召回内容混杂。

**标题怎么处理：**

- 只在「一个可独立成立的主题」处保留 `#` / `##`；
- 「部署拓扑」「一、扩容管理组件」「3.2 数据来源」这类**从属小节**降级为加粗引导句：`**部署拓扑：** 正文……`；
- 父标题下如果只有子标题没有正文，补一句导语，否则会切出只剩标题的空块。

**从 Word / docx 转来的机械坑：**

| 现象 | 处理 |
| --- | --- |
| 每段、每张图之间都有空行 | 按上面的语义判断整体压掉 |
| 列表全是 `1.`（`1. 1. 1. 2.`） | 读 docx 的 `w:ilvl`：level 0 → `1.`，level 1 → 缩进 `-` |
| 步骤编号中途从 1 重新开始 | 按模块重新连续编号；「注意」下的条目降为子项 |
| 标题层级 4~5 级 | 只保留到模块级，其余降为加粗引导句 |
| 拓扑、矩阵写成表格 | 改嵌套列表：`- **规模：**` 下挂 `- 组件（类型）：节点 1 ✅` |
| 图片是 EMF/Visio 预览 | 转 PNG，否则渲染器不显示 |
| 文档标题是普通段落 | 补 `#`，原有标题整体降一级 |

**纯文字步骤要编号**：从 Word 转来的「点击 A」「再点击 B」常是没有编号的段落，补成 `1. 2. 3.`，否则读者无法指出「第 3 步失败」。

## 四、写完自检

```text
python scripts/check_doc.py <文档路径> [分段上限，默认 2048]
```

以上为照片原接口记法，方括号表示可选参数，不要原样输入；在本技能目录中执行，例如 `python scripts/check_doc.py "文档.md" 2048`。从其他目录运行时使用脚本与文档的绝对路径。脚本只读文档，不改写文件，不上传或发布内容；退出码 `0` 为通过，`1` 为需处理或人工复核，`2` 为参数/文件/编码错误。保留表格导致多块时仍可能返回 `1`，按下述人工规则判断，不能只为退出码通过而强行合并主题。

脚本按 Dify 规则模拟切块，报告：块数、块数与标题数之差、每个标题下切出几块、标题内部空行的行号、最长块、小于 60 字符的碎块、`###` 数量、连续空行、表格块、表格前的孤儿引导句。退出码 1 表示有违规。

先看硬指标：**块数必须等于标题数**（表格是唯一例外）。再人工核：

1. **问题分析类**：现象与根因自洽；判断章只有判据、排除项、盲区；预防每条对应一个已确认原因且生产会执行。
2. **通用类**：主题之间没有混在一起；从属小节都已降级；步骤编号连续；图与说明同块。

## 五、反例

| 反例 | 为什么错 |
| --- | --- |
| 标题下、段与段之间留空行 | 每个空行就是一个切分点，同一节被切成多段碎块 |
| 用 `###` 切小节 | 每个小标题开启新 Document，章节被拆散 |
| 表格前只写一句短引导 | 表格强制前有空行，引导句被切成几十字符的孤儿块 |
| 单块超过分段上限 | 会在无标题处被硬切，标题与正文分离 |
| 为了少块把两个主题压在一起 | 召回内容混杂，答非所问 |
| 通用类文档按模板重排章节 | 原文结构被打乱，内容可能丢失 |
