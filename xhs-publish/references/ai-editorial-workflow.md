# AI 图文的配图与验收流程

## 已确认的视觉方向

- 小红书：浅纸白＋克莱因蓝，Guizang Swiss 网格。默认五页：总览、三条信息各一页、能力边界总结。
- 公众号：gzh-design 的 graphite-minimal 注册组件，单独横版和方版封面，正文首图＋三张章节图。
- 图片是依据来源制作的原创信息图，不是产品截图；无亲测证据时明确采用公告／媒体报道口径。
- 不改写 Guizang 或 gzh-design 上游技能；它们负责版式规则，本 skill 负责交付与平台验收。

## 一套视觉系统，所有小红色内容共用（2026-11-14 定）

账号此前同时跑了纸白蓝、深蓝满版、墨绿列表、深色新闻表格四套皮，同一主页看着散。**从今天起只保留纸白＋克莱因蓝一套，深色不做满版。**

固定 token，不允许某一期另配色：

| 用途 | 值 |
|---|---|
| 纸白底 | `#FAFAF8` |
| 卡片面 | `#FFFFFF`（仅列表/相框类用） |
| 墨（主字） | `#0A0A0A` |
| 克莱因蓝（强调） | `#002FA7` |
| 次级灰 | `#52525B` / 页脚 `#71717A` |
| 细线 | `#E4E4E7` |

固定卡型五种，全部 1080×1440：**封面、单点结论、数字指标、对比双栏、清单**。

- 清单每页最多 6 行，超出拆页，不缩小字号硬塞；122px 标题类字号下限 56px，正文下限 30px，页脚 24px。
- 封面必须白底、大字标题＋一句说明＋`n/N`；标题按语义断行，不出现孤字。
- 深色只能作为白底上的小色块（如强调数字），不做满版背景。
- 页眉固定 `栏目 / 日期`，页脚固定 `来源名 · 页码`，全账号一致。
- 改版式只改渲染器，不在单期成稿里改颜色、字号。

已按此统一：

- `scripts/render-ai-editorial.mjs`：AI 工具五页图文。
- `scripts/render-github-intro.mjs`：GitHub 榜单总览（原墨绿改纸白＋克莱因蓝）。
- `scripts/render-news-cards.mjs`：科技 24 小时／新闻清单。spec 只写 `kicker/date/title/lead/items[]`，每项含 `tag/title/detail/source`；默认每页 4 条，超过自动分页，首页是封面。**不再在任务目录里手写深色表格图**。

```powershell
node scripts\render-news-cards.mjs --spec <news.json> --out <images目录>
```

渲染器会检查每页文字是否越过页脚、是否被截断，溢出直接失败，不产出半张图。

## 小红书先审推广意图，再做卡片

执行 [推广与站外引导审阅](<promotion-review.md>)。文字改稿前先审原始文稿，卡片产出后再逐张打开检查；短正文、附录、五页图文和尾页使用同一套内容标准，不能把正文删掉的安利/下载/注册/购买指引搬到图里。

- 免费、价格、权益、产品推荐和“换过去试”等组合需要重点复核，不是只扫描网址或品牌黑名单。中性产品报道也需要真实来源与适用条件，不能承诺不被平台识别。
- 末页应总结问题、证据和能力边界，不自动追加下载/换用建议、优惠或私信领取入口。已有原意属于推广时，提出实质改稿方案并在授权内执行，不靠版式掩饰。
- 原创信息图也要看实际文字、界面元素、二维码和联系方式；“不是截图”或“已去链接”不是合规凭证。生成后的最终文件绑定 SHA-256、完整可见文字及具体视觉检查记录，修改后重新审。
- 未审图片、渲染后哈希改变或尚有明确站外 CTA，停止在本地，不上传到发布页试探审核。图片审阅是执行者声明，不等于脚本自动 OCR/语义识别，更不是平台过审保证。

## 先确定每页的信息任务

1. 总览只交代本期主题和三条消息，不放长段落。
2. 详情页优先在大字、指标、结构、对比之间变化；一页只承担一个主要信息任务。
3. 指标写明单位、比较对象、思考档位、条件和来源。没有证据就不用该指标，绝不为版式凑数字。
4. 末页总结评估边界，而不是机械重复产品推荐。平台已给出推广／导流修改建议时，先阅读原因，实质性删掉导流与购买引导；不拆字、谐音、遮掩词或新建重复笔记规避处置。
5. 标题按内容主动断行，禁止孤字、孤词、数字与单位意外拆行。内容溢出先精简措辞或调整布局，不把正文缩小到手机难以阅读。

## 可复用渲染入口

`../scripts/render-ai-editorial.ps1 -Spec <绝对路径/editorial.json> -Out <绝对路径/images>`

- 读取本机 Guizang Swiss HTML seed，保留语义 token，加入本地 Noto Sans SC 可变字体。
- 使用普通 Node 与全新临时无登录 Chrome，随机端口，禁止 9333／9334／9335；连接前严格核验端口 PID 与完整 user-data-dir。
- 不用旧版深蓝单封面的 make-cover2，不用缺依赖后静默降级。
- 产出五张 1080×1440、2100×900 和 1080×1080 封面，以及三张章节图。两个封面独立编排，不互相裁切。
- 每块画板做几何越界检查，结果见输出目录上一级 layout-check.json。失败图只写 layout-debug；不能发布。
- finally 关闭精确临时 profile，渲染回执里的 browserCleanup 必须 remaining=0。

当前示例 JSON 使用 overview、gemini、claude、assistants、decisions 等历史字段，分别代表总览、指标页、三条结构页、双列对比页和边界总结页；字段名不授权复用示例事实。双栏页眉可用 comparisonKicker 按本期内容填写，不残留“个人智能体”等旧分类；这不改变字体、颜色和版式 token。模板适合这些内容结构时才用；下一期内容结构不合适，应按 Guizang 原流程重新实例化 Swiss 模板，不强行捏造比较或数据。

## 公众号正文图与本地手机预览

公众号用 wechat-publish 的 `htmlFile`＋`inlineImages`。先按 gzh-design 生成纯 section／内联样式／span leaf 片段，再跑一次 accent（见下），最后校验错误警告归零。

**两端同一个识别色**：公众号正文保持石墨灰，只用克莱因蓝 `#002FA7` 做章节序号和关键词下划线，和红书卡片同源；不往长文正文里加大面积蓝。生成后用 wechat-publish 的 `scripts/theme-accent.mjs` 统一替换，不靠每次手改，也不改 gzh-design 上游主题：

```powershell
node <wechat-publish>\scripts\theme-accent.mjs --in <原始section.html> --out <article.wechat.html>
```

它只改三类：章节序号色、关键词下划线、引言卡左竖线；其余 HTML 原样保留。输入必须是单个 `<section>` 片段，已有同名输出会拒绝覆盖。每张图一个唯一 `<!--WECHAT_INLINE_IMAGE:id-->`；正文首图为本期横版封面。`type:"ai-update"` 和 `coverFromBody:true` 禁止缺图、正文被剥样式或封面不匹配后继续保存。

`../scripts/preview-wechat-local.mjs --job <公众号任务绝对路径>` 会把已有本地图片绑定到预览 HTML，并在 390px 宽度检查水平溢出、加载和正文排版，生成 top/full PNG。它只是本地排版证明，不是公众号保存成功证据；禁止拿预览外壳当 htmlFile 发布。

逐页检查：目录确实对应正文三条内容，导语有左右边距，图中标题断行合理，字号清晰，图与章节匹配。实际平台上传后仍须核验图片数量、顺序、正文、关键样式、封面及显式保存提示。

## 平台操作与结果留存

- 必须先加载两个当前发布 skill。原笔记只走 edit；精确标题＋日期定位，保留同一 noteId；不走 post，不删除或新建替代。
- 公众号永远草稿，绝不 submit／发表／群发。保存结果未知时先核对草稿箱，不盲目另建。
- 普通 Node 路径见本机执行说明；不可因 bundled Node 的进程／文件限制而设置跳过核验。
- 两个 port-profile helper 现在拒绝 PUBLISH_SKIP_PROFILE_VERIFY=1；PID-only、不可读 profile、进程非 Chrome／Edge、监听变化都不能成功。
- `../scripts/run-cli-safe.mjs --platform xhs|wechat --out-prefix <绝对前缀> -- <命令参数>` 直接把子 CLI 的 UTF-8 字节写入独立 JSON／err 文件，避免 Windows PowerShell 文字重编码；已有回执拒绝覆盖。
- 区分出图通过、预填通过、提交成功、审核状态；不把前三者当审核通过。真实平台操作结束均检查精确 profile 清理。
