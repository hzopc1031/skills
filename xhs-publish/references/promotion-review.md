# 小红书推广与站外引导审阅

## 这次反馈能证明什么

依据用户提供的“笔记审核详情”截图，平台列出的历史问题是“笔记存在推广其他平台的内容”，处置为限制推荐和搜索展示，且明确说广告投放和蒲公英流量不受该项处置影响。不能把这一条扩大成整账号封禁或所有渠道停流。

截图顶部注明“当前笔记已修改，此页面仅展示历史违规记录”。因此它不能证明修改后的笔记仍在受限，也不能证明已经解除；提交/保存成功同样不能证明审核或推荐恢复。

截图列出五类可能场景：展示其他平台界面、引导去其他平台搜索浏览、以种草/科普/教程/测评宣传其他平台、福利/优惠跳转，以及推荐其他平台产品/服务/会员或付费内容。这些是平台给出的原因类别，不是本工具验证过的完整规则，也不能推断每个品牌提及都会触发处置。

## 三段标记文字的风险分析

1. **“全球免费用户就能用，Google 搜索、Sheets、Gemini App……”**：免费权益、开放范围和多个站外产品组合，带有利益宣传色彩。还应核实“今天起”“全球”“都能用”的来源、地区、账户和开放批次，不能只删产品名假装改成事实报道。
2. **“蚂蚁灵光……主要靠支付宝账单帮你分析消费……已经能替你办一些具体的事”**：将产品能力直接转成对读者的使用收益，可能被理解为安利。审核截图没有给出精确到词的因果，不能认定仅“支付宝”一词就是触发原因。
3. **“Gemini 4……便宜和聪明……可以直接换过去试”**：价格/效果背书与明确换用行动相连，站外引导意图最直接。只删 URL 或把“换过去试”换成暗号，意图仍在。

这些分析不验证截图中的模型版本、价格、发布时间或功能事实，也不保证去掉某一句后就恢复流量。

## 改稿原则

- **报道不等于推荐**：必要的品牌、来源和仓库名可以保留，但要区分有来源的事实、评论、推广和行动号召。中性语气本身也不是平台免审凭证。
- **先处理意图，再处理字面**：对明确下载、注册、迁移、购买、站外搜索/领取或联系方式转移的内容，提出实质删改建议；没有改稿授权就停，不擅自改变作者观点或商业目的。
- **不编造事实**：保留原文可证实的版本、数字和条件；缺少依据的“免费/最便宜/全量开放”等标为待核实，不换成另一个同样没有依据的说法。
- **不提供伪装回退**：不拆字/谐音/零宽字符、不把链接藏在图里或转移到评论/主页/私信、不靠删帖重发回避处置。
- **技术示例不是 CTA**：教程里的代码、命令、URL 可能有解释必要，先按用途人工判断；不能因为见到命令就一律认定推广，也不能用“教程”标签自动豁免站外指路。

可用的中性写作结构是“所讨论的问题 → 有来源的能力/限制 → 适用条件和证据缺口”，而不是“平台名 → 免费便宜 → 赶紧去换”。这只是结构建议，不授权虚构报道或承诺过审。

## 审阅面与顺序

1. 原始标题/覆盖标题、正文、caption、话题、附录、GitHub 项目文案、卡片标题/脚注和完整转图文本，在链接清洗与正文缩短前保留审阅上下文。
2. 再审最终实际展示文字；不能只看短正文，忽略迁入图片的原全文、总评或附录。
3. 逐张打开最终本地图片：封面、所有详情、尾页、用户配图，包括小字、截图界面、二维码和站外联系方式。脚本只核对审阅记录与文件哈希，不自称已经看过像素或执行了 OCR。
4. 未来另获原帖编辑授权时，读取同一笔记的 before，审实际保留/替换后的标题、正文、话题和原图；保留内容有风险就停止并说明需要哪些额外改稿授权，不擅自清洗写回。
5. 全部检查与身份/图片来源核验完成后，才允许已授权的预填/保存/发布。`submit:false` 一直阻止提交；预检通过不改变它，也不为发布增加授权。

原始文本的进程内快照与调用方 JSON 中的“original”字段区分，不能用伪造的清洗后快照冒充原稿。只对实际会参与当前操作的字段审阅：编辑任务中被忽略的旧顶层 content/caption/topics，不变成新正文。

**兼容性变化：** 0.9.0 不再允许无本地图片的旧版平台一键排版路径在最终卡片未审时继续。源稿文字无命中，也仍是 pendingGenerated；先独立本地制卡、检查最终文件再走图文，不以预填向已登录平台上传来试探审核。

## 离线命令与失败含义

```powershell
node scripts/xhs.mjs preflight --job "任务.json" --kind post
node scripts/xhs.mjs preflight --job "编辑任务.json" --kind edit
```

`preflight` 不读取账户配置、不登录、不连接 CDP、不上传、不写回任务。输出是本地风险报告，不是平台审核结果。出现明确引导、未解决语境或图片待审时为 `CONTENT_REVIEW_REQUIRED`（退出9）；参数或文件错误仍按原有 `USAGE`。

- **block**：明确的站外行动/联系方式转移；不能用人工“通过”声明覆盖，只能实质改稿并重新检查。
- **review**：利益推荐、安利、来源或开放范围等待核实语境；可能误报，要逐项解释，不能用笼统 `approved:true` 跳过。
- **info**：观察或限制说明，不代表平台给出过结论。
- 无命中只表示该启发式扫描未命中已实现规则，不表示没有其他违规类型。

编辑离线预检不知道未读到的保留正文和原图，只能报告 pendingExisting；不能因此擅自打开原帖。自动生成的卡片尚未产出或未看过时是 pendingGenerated/图片待审，不可把未知写成已审核。仅余这些未知状态时，可以在用户已有相应授权下只读核对同一原帖或独立本地生成卡片；尚有明确文字风险或已知图片待审则先解决。程序 known 阶段只允许进行这类后续检查，不是最终放行，final gate 仍必须在第一次改写/上传/保存前通过。

## 有边界的人工记录

审阅记录放在新的任务文件顶层 `promotionReview`，只记录真的审过的内容，原任务和源稿不覆盖。记录不是身份认证或自动审核证明；脚本仍不能证明填表者真的看过图片。

**文本误报**使用 `promotionReview.text` 数组，每项包含实际报告给出的 `findingHash`、`decision: "neutral-reporting"`、具体 `rationale` 和 `reviewer`。哈希绑定规则、命中片段和对应文本表面的全文，不手写猜测；该表面改稿后以新报告重新审阅。block 不能靠此放行。

**每张新图**使用 `promotionReview.images` 数组，每项包含：
- `sha256`：实际最终文件哈希；换图、改字或重新渲染导致哈希变化，原记录失效。
- `visualChecked: true`：确已逐张查看视觉内容的声明。
- `visibleText`：完整可见文字转录；纯图无字可为空，但说明中要写清。
- `conclusion: "no-outbound-promotion"`、具体 `rationale`、`reviewer`。

转录文本仍要经过相同风险检查。缺转录/说明、仅有 `true`、只有文件路径、格式头有效或上传身份相同，都不代表推广风险检查完成。

**保留原图**使用 `promotionReview.retainedImages`，同样包含视觉声明、转录、结论、说明和审阅者，并绑定 `noteId` 与有序原图来源的 `sha256`；所需哈希由实际原笔记快照生成。不能从当前历史处罚图推造原帖的图片审阅记录。

每条 `rationale` 至少 12 个字符、`reviewer` 至少 2 个字符，并应写具体依据；字数不是审阅真实性证明。同一 `findingHash` 或同一图片 SHA 只能有一条记录，避免互相冲突的重复声明。

这些记录不应包含 cookie/token/登录数据。它们及风险报告可能有业务原文片段，仅存本地，不默认上传 GitHub 或其他平台。

## 验证与结果用语

本轮只优化 Skill 与离线测试，没有为本任务打开、编辑、重发或删除实际笔记。旧版 Skill 已完整备份到技能扫描目录之外。

必须区分“离线预检完成”“预填/保存成功”“平台审核通过”“推荐或搜索恢复”。没有对应平台证据，只报告实际完成的那一级；不能用自动提交成功或历史违规页推导审核及流量结论。
